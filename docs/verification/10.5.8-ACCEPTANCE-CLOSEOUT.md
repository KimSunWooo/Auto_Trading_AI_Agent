## 2. Live cutoff 양방향 검증

### 구현 확인

`include_current_receive`는 `as_of` 생략 + live-compatible 모드에서만 켜진다.
각 live collector는 `access_as_of = received_at`으로 `collect_accessible`을
호출한다. `datetime.max`로 바꾸거나 `is_accessible_at`을 건너뛰지 않는다.

- 요청 시작 `t0`보다 늦은 정상 수신 `t1`은 현재 관측에 포함된다.
- 공급자별 수신 시각이 달라도 journal / envelope / fingerprint의
  `analysisAsOf`는 수집 이후 `judgment_as_of`와 같다.
- `sourceReceivedAt` / `tradableAt`이 최종 cutoff보다 미래이면 제외된다.
- 명시적 과거 `as_of`에는 이후 수신이 노출되지 않는다.
- 전 공급자 실패에서도 cutoff와 `DATA_UNAVAILABLE` / `BLOCKED`가 일치한다.
- FIXTURE `evaluate()`는 계속 `FIXTURE_AS_OF`를 쓴다. REPLAY는 snapshot
  restore이며 live를 재호출하지 않는다.

### 추가로 재현된 결함과 최소 수정

재현: 공급자가 `eventOccurredAt=2099`를 주고 `sourceReceivedAt` /
`tradableAt`만 현재이면, `is_accessible_at`이 `eventOccurredAt`을 보지
않아 현재 관측에 포함됐다. in-cycle receive가 모든 시간 검증을 끈 것은
아니지만, 잘못된 미래 발생 시각이 접근성 필터를 우회했다.

최소 수정: `collect_accessible(..., reject_future_event_occurred=True)`를
**Live collector만** 켠다. FIXTURE/REPLAY 기본값은 False라서 캘린더형
미래 `eventOccurredAt` 경로는 그대로다.

회귀: `tests/test_live_acceptance_closeout.py`

## 3. 동시 요청 실행별 상태

방법: `create_app(service)`의 **공유** `AnalysisService`에 대해
`threading.Event`로 교차시킨다. sleep에 의존하지 않는다.

교차 순서:

1. 요청 A (`005930`) market 수집 성공 후 대기
2. 요청 B (`000660`) market 실패로 `last_diagnostics` 기록
3. A가 이어서 collect 반환
4. B가 `_capture_provider_diagnostics`를 먼저 수행한 뒤 A가 수행

결과: **응답은 교차하지 않았다.**

| 항목 | A (005930) | B (000660) |
| --- | --- | --- |
| ticker | 005930 | 000660 |
| market status | OK | DATA_UNAVAILABLE |
| readiness | BLOCKED 아님 | BLOCKED + MARKET_DATA_UNAVAILABLE |
| decisionId / envelope.proposalId / journal | 서로 다름, ticker 일치 | 서로 다름, ticker 일치 |
| LLM thesis | 성공 payload ("Observation only") | fail-closed "LLM unavailable" |

코드 변경 없음. “sync FastAPI + 단일 service = 직렬”로 단정하지 않았고,
응답 경로(`evaluate` 로컬 `CollectionResult` / `readiness` / `llm_assist`)는
실행별로 분리되어 있다.

### health의 “최근 실행”

`GET /health` → `collect_health`:

- `last_market`가 있으면 그 결과를 쓰고, 없으면 `005930`을 다시 collect한다.
- news / disclosure / macro / scheduled는 **항상 재수집**한다.
- LLM은 `llm.last_diagnostics` (last-writer)를 읽는다.
- `EventPipelineHealth`의 “last run succeeded”는 **프로세스 마지막
  evaluate 성공**이지, 방금 본 HTTP 요청의 전용 핸들이 아니다.
- `service.last_*`, `provider_diagnostics`, 각 collector `last_diagnostics`는
  last-writer이며 요청 범위가 아니다.

검증 범위: 공유 service의 `evaluate()` 두 스레드. uvicorn threadpool의
실제 HTTP 동시성과 동일한 공유 객체를 쓰지만, 프로덕션 서버 부하 테스트는
하지 않았다.

## 4. 수정 6건 증거 연결

기존 `tests/test_live_acceptance_1058.py`를 다시 쓰지 않았다.

### 4.1 Live 현재 관측 cutoff

- 재현: `as_of` 생략, DART 수신이 `t0+45s`. 이전 구현은 수신을 `t0`에
  고정해 이후 수신을 버렸다.
- 원인: live current의 접근 cutoff가 요청 시작과 같았음.
- 수정: `analysis/service.py` `include_current_receive`; live collectors의
  `access_as_of = received_at`; `judgment_as_of = now()` after collect.
- 회귀: `test_live_current_observation_keeps_data_received_after_request_start`
  + closeout `test_t1_after_t0_is_in_current_observation_and_matches_final_cutoff`

### 4.2 DEGRADED 상태 병합

- 재현: disclosure DEGRADED + 나머지 NO_EVENT/optional NOT_CONFIGURED →
  전체가 OK로 승격.
- 원인: `merge_external_status`가 부분 장애를 OK로 접음.
- 수정: `analysis/service.py` `merge_external_status`가 DEGRADED를 보존.
- 회귀: `test_dart_degraded_is_not_merged_to_overall_ok`

### 4.3 deadline 이후 응답 거절

- 재현: transport가 total deadline 이후 HTTP 200을 반환해도 성공 처리.
- 원인: 응답 본문 도착만으로 circuit success.
- 수정: `adapters/live/http.py` — monotonic deadline 이후 응답은
  `TIMEOUT`, circuit failure.
- 회귀: `test_deadline_elapsed_response_is_not_success`

### 4.4 News ID 공급자 구분 및 index 의존 제거

- 재현: 다른 source의 동일 vendor `id`가 같은 `record_id`; id 없는 기사가
  배열 인덱스에 묶임.
- 원인: `news_{source_id}` / `news_{index}:...`
- 수정: `adapters/live/news/parser.py` `stable_news_record_id(source, source_id)`
  (sha256 `source\0source_id`). 인덱스 경로 제거.
- 회귀: `test_news_ids_include_source_and_avoid_index_only_identity`

**News 수정·철회는 ID 충돌 수정만으로 완료가 아니다.** Live parser는
`[CORRECTION]` / `[RETRACTION]` / `[RELATED:]` 태그를 body에 붙인다.
클러스터 유지·`RETRACTED` 상태·삭제 거부는
`tests/test_event_retraction.py`의 Event Intelligence `engine.retract`
경로다. Live 기사 수정본이 기존 이벤트를 갱신하는지의 E2E는 이번
closeout에서 완료로 보고하지 않는다.

### 4.5 손상 OHLCV가 섞인 응답의 DEGRADED

- 재현: volume 없는 bar를 skip한 뒤 나머지가 있으면 OK.
- 원인: skip 카운트가 상태에 반영되지 않음.
- 수정: `market/parser.py` `MarketParseOutcome.skipped_incomplete`;
  collector가 유효 row가 남아도 DEGRADED.
- 회귀: `test_mixed_valid_and_corrupt_ohlcv_is_degraded_not_ok`

### 4.6 DART 페이지 중복 제거

- 재현: 같은 `rcept_no`가 두 페이지에 있으면 레코드 중복.
- 원인: 페이지 list를 그대로 concat.
- 수정: `adapters/live/dart/__init__.py` `rcept_no` unique merge.
- 회귀: `test_dart_duplicate_pages_do_not_duplicate_records`

## 5. 공급자 수동 검증 runbook (실제 호출 금지 — 절차만)

검증 대상 SHA는 이 보고서를 담은 로컬 HEAD (`git rev-parse HEAD`)이다.
원격 main은 아직 `ff61696`이다.

비밀은 이름만 기록한다. 값은 출력하지 않는다.

공통 기록 항목 (매 공급자):

- 전체 commit SHA
- 공급자/adapter 이름
- 사용한 환경 변수 **이름**
- 요청 시작 / 수신 / 판단 cutoff (`analysisAsOf`)
- collection status / error_code / readiness
- `decisionId`, `dataMode`, `isOrder`
- 기대 결과와 성공·실패 판정
- 비밀 제거 증거 위치: `docs/verification/redacted-evidence/`

### 존재하는 인터페이스 (없는 명령을 만들지 말 것)

| 방법 | 역할 | 단독 공급자 검증? |
| --- | --- | --- |
| `python -m ai_investment_agent.cli.observation_smoke --ticker 005930` | 필수 공급자 일괄 evaluate | 아니오. market+disclosure+macro+news+llm |
| `POST /analysis/evaluate` 또는 `POST /observation/evaluate` | 동일 파이프라인 | 아니오 |
| `GET /health`, `GET /providers/health` | 프로세스 스냅샷 | 아니오. “최근 실행”은 위 3절 |
| `NO_NETWORK=1 pytest` | mock/fault injection | 장애 시나리오는 여기만 |

단독 collect CLI (`ai-market-ping` 등)는 **없다**. 문서에 없는 명령을
적지 않는다.

추가로 필요한 작은 작업 (미구현, 자동 시작하지 않음):

- 공급자별 `collect()`만 호출하는 읽기 전용 inspect 헬퍼
- 응답을 redacted JSON으로 저장하는 옵션
- health를 request-scoped로 바꿀지는 이번 범위 밖

### 공통 사전 조건

- `AI_DATA_MODE=LIVE_OBSERVATION`
- `NO_NETWORK` 미설정 (수동 실행 시). CI/`NO_NETWORK=1`에서는 smoke가
  exit 2로 거부한다.
- `.env`는 로컬만. 커밋 금지.
- 기대 터미널 아티팩트: `TradeProposalEnvelope` v1, `isOrder=false`
- scheduled는 optional. `NOT_CONFIGURED`를 연결 성공으로 위장하지 말 것.

장애 재현은 기존 mock/fault injection만 사용한다. 실제 공급자에 고의
인증 실패나 quota 초과를 유발하지 않는다.

### Market — `LiveMarketDataCollector`

- Adapter: `live-market`
- Env 이름: `MARKET_DATA_BASE_URL`, `MARKET_DATA_API_KEY`(optional),
  timeout/retry/RPS/circuit (`MARKET_DATA_*`)
- 계약: `GET {MARKET_DATA_BASE_URL}/market/{instrument}?asOf=`
- `BASE_URL`만 넣으면 완료가 아니다. 위 JSON 형태(instrument, timestamp가
  있는 가격/OHLCV)가 아니면 전용 adapter가 필요하다.
- 확인: instrument 일치, `currentPrice.value`, OHLCV 완전성,
  `eventOccurredAt`/`sourceReceivedAt`/`tradableAt` ≤ cutoff,
  volume 누락 bar는 0으로 채우지 않고 skip → 남으면 DEGRADED
- 성공: status OK 또는 정당한 NO_EVENT/DEGRADED. `isOrder=false`
- 실패: SCHEMA_INVALID, NO_ACCESSIBLE_DATA, TIMEOUT, HTTP_*
- 기존 장애 테스트: `test_mixed_valid_and_corrupt_ohlcv_is_degraded_not_ok`

### DART — `LiveDisclosureCollector` (OpenDART `list.json`)

- Adapter: `opendart`
- Env 이름: `DART_API_KEY`, `DART_BASE_URL`, `DART_CORP_CODE` 또는
  `DART_CORP_CODE_<TICKER>`, `DART_*` timeout/retry
- 확인: ticker↔corp_code 매핑 필수. 응답 `corp_code`/`stock_code` 일치.
  페이지 `total_page` 완결. `rcept_no` 중복 없음.
  `rcept_dt`는 날짜(UTC midnight), `sourceReceivedAt`은 실제 수신.
- 성공: OK 또는 013 → NO_EVENT. COMPANY_MISMATCH / MISSING_CORP_CODE는 실패.
- 페이지 실패는 DEGRADED(`PAGINATION_INCOMPLETE`). 전체 OK로 올리지 말 것.
- 기존 장애 테스트: `tests/test_live_dart.py`, `test_dart_duplicate_pages_*`

### Macro — `LiveMacroCollector`

- Adapter: `live-macro`
- Env 이름: `MACRO_BASE_URL`, `MACRO_API_KEY`(optional), `MACRO_*`
- 계약: `GET {MACRO_BASE_URL}/macro?asOf=` vendor-neutral JSON
  (`items`/`observations`/`list`). 공식 통계청/FRED 원본이 이 형태가
  아니면 **전용 adapter 필요**. BASE_URL만으로 연결 완료가 아니다.
- 빈 성공 피드 = NO_EVENT. 전송 실패 = DATA_UNAVAILABLE.
- 기존 장애 테스트: `tests/test_live_macro.py`

### News — `LiveNewsCollector`

- Adapter: `live-news`
- Env 이름: `NEWS_BASE_URL`, `NEWS_API_KEY`(optional), `NEWS_*`
- 계약: `GET {NEWS_BASE_URL}/news?ticker=&asOf=`
  (`articles`/`items`/`list`). Reuters/Bloomberg 원본 API는 이 계약이
  아니면 전용 adapter 필요.
- ID: `sha256(source + NUL + source_id)`. 수정/철회 태그는 4.4 주의.
- 기존 장애 테스트: `tests/test_live_news.py`, news ID acceptance

### LLM — `LiveLlmProvider`

- Adapter: `live-llm`
- Env 이름: `LLM_API_KEY`, `LLM_BASE_URL`, `LLM_MODEL`, `LLM_TEMPERATURE`,
  `LLM_PROMPT_VERSION`, `LLM_*` timeout/retry
- 계약: OpenAI-compatible `POST /chat/completions`, `response_format=json_object`
- 실행 전 정할 항목: 호출 횟수 상한, 예상 토큰/비용, 모델, temperature,
  실패 시 즉시 중단 여부. 이 closeout은 유료 호출을 시작하지 않는다.
- 확인: 설정 모델이 응답 `model`/`modelVersion`에 남는지,
  `promptVersion`이 content에 붙는지, 실패 시 fail-closed NO_TRADE.
- health는 LLM을 호출하지 않는다 (`_complete_llm_assist`만).
- 기존 장애 테스트: `test_llm_diagnostics_follow_the_latest_call_*`,
  `tests/test_live_llm.py`

### scheduled — `UnconfiguredScheduledEventCollector`

- LIVE는 fixture 캘린더를 섞지 않는다. `SCHEDULED_USE_FIXTURE`는 무시.
- 상태: `DATA_UNAVAILABLE` + `NOT_CONFIGURED`. NO_EVENT나 연결 성공이 아니다.
- 단독 설정 인터페이스 없음. 그대로 기록한다.

### 수동 실행 시 판정

`observation_smoke` 분류:

- exit 0: 필수 공급자 호출됨, 실패 아님. `HEALTHY_NO_TRADE`도 성공.
- exit 1: 필수 공급자 실패/미설정/미호출
- exit 2: `NO_NETWORK` 또는 mode 거부

응답에서 `isOrder`가 true이거나 broker/ATS 필드가 켜지면 즉시 실패.
